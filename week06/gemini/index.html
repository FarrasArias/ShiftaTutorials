Generative Music

We now have all the building blocks: oscillators, envelopes, scales, FFT analysis, filters, delay, reverb, and microphone input. In this final tutorial, we bring everything together to build systems that compose music on their own: generative music.

The term was coined by Brian Eno in the 1990s, though the concept is much older. Eno described generative music as systems that produce "ever-changing, ever-different music": music that is not performed or sequenced by a human, but emerges from a set of rules and constraints.

Weighted Random Selection

Pure randomness treats every note as equally likely, which produces a flat, aimless quality. Real music has tendencies: certain notes appear more often, melodies tend to move in small steps rather than large jumps.

We can introduce tendencies with weighted random selection:

function weightedRandom(items, weights) {
  let total = 0;
  for (let i = 0; i < weights.length; i++) {
    total += weights[i];
  }
  let r = random(total);
  let sum = 0;
  for (let i = 0; i < items.length; i++) {
    sum += weights[i];
    if (r < sum) return items[i];
  }
  return items[items.length - 1];
}

// Root and fifth are most likely; other notes less so
let notes   = [0, 2, 4, 7, 9];
let weights = [4, 1, 2, 3, 1];
let step = weightedRandom(notes, weights);

By giving the root (0) and fifth (7) higher weights, the melody gravitates toward these "home" tones, creating a sense of key and stability even though the specific sequence is random.

A Step Sequencer

A sequencer plays notes at regular intervals (steps). Unlike the random timing above, a sequencer has a steady pulse: a tempo. Each step can have a note, a rest (silence), or different parameters:

Markov Chains: Memory in Randomness

A Markov chain adds a simple form of memory: the next note depends on the current note. Instead of choosing from a global probability distribution, each note has its own set of probabilities for what comes next.

We define this as a transition table:

// Each key maps to an array of possible next notes
// Notes that appear more often are more likely
let transitions = {
  0:  [0, 2, 4, 7],      // from root: can go anywhere
  2:  [0, 4, 4, 2],      // from 2nd: tends toward 3rd
  4:  [2, 7, 7, 4],      // from 3rd: tends toward 5th
  7:  [0, 0, 4, 9],      // from 5th: tends back to root
  9:  [7, 7, 0, 4]       // from 6th: tends toward 5th
};

let currentNote = 0;

function nextNote() {
  let options = transitions[currentNote];
  currentNote = random(options);
  return currentNote;
}

The result is a melody that has local coherence: it tends to move in steps rather than jumps, and it gravitates toward certain pitch centers: while still being unpredictable at a global level. This is much closer to how real melodies work than pure randomness.

Design Principles for Generative Music

Some principles that make generative systems sound more musical:

  • Constrain the pitch palette. Use a scale: pentatonic, modal, or microtonal. Fewer pitch options often sound better than more.
  • Vary the rhythm, not just the notes. Random timing (within bounds) creates organic feel. Regular timing creates pulse. Both are valid; mixing them creates texture.
  • Use space. Not every step needs a note. Rests and silences are musical events. A 25% chance of silence per step makes a big difference.
  • Layer slow and fast. Combine a slow-changing bass drone with faster melodic gestures. Different time scales create depth.
  • Let effects do work. Reverb and delay turn sparse notes into dense textures. A single plucked note through a long reverb becomes a pad.
  • Add tendencies, not rules. Weighted probabilities and Markov chains create coherence without rigidity. The system should surprise even you.
