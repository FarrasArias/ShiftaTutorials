Microphone & Reactivity

Until now we've been generating sound with oscillators. But some of the most compelling creative coding work uses live audio input (the microphone) as the driving force for visuals.

p5.AudioIn: Accessing the Microphone

p5.AudioIn captures audio from your computer's microphone (or any audio input device). The browser will ask for permission the first time:

let mic;

function setup() {
  createCanvas(400, 400);
  mic = new p5.AudioIn();
  mic.start();  // request permission and begin capturing
}

Important: microphone access only works over HTTPS or localhost. The p5.js web editor runs on HTTPS, so it works there. If you're running a local server, use localhost.

Amplitude-Reactive Visuals

The simplest and most effective approach: use p5.Amplitude to measure the microphone's loudness and map it to visual parameters.

open example in new window 
let mic, amp;

amp.getLevel() returns the RMS (root mean square) amplitude: a smoothed measure of loudness ranging from 0 (silence) to approximately 1 (very loud, close to the mic). In practice, normal room sounds produce values around 0.01–0.1, and you'll rarely see values above 0.5 unless you're shouting directly into the microphone.

This means you should calibrate your mappings. Instead of mapping from 0–1, map from 0–0.3 or 0–0.5 for more responsive visuals at normal volumes.

Smoothing: Taming Jittery Data

Raw amplitude data changes rapidly and can make visuals jittery. There are two approaches to smoothing:

1. Built-in smoothing: p5.Amplitude accepts a smoothing parameter (0 to 1):

amp = new p5.Amplitude(0.9);  // high smoothing: slow, flowing
amp = new p5.Amplitude(0.3);  // low smoothing: fast, responsive

2. Manual smoothing with lerp: for more control, blend each new value with the previous one:

let smoothLevel = 0;
let smoothing = 0.85;

function draw() {
  let rawLevel = amp.getLevel();
  smoothLevel = lerp(smoothLevel, rawLevel, 1 - smoothing);
  // smoothLevel changes gradually toward rawLevel
}

The lerp() approach is useful because you can use different smoothing for different parameters: fast smoothing for something that should feel punchy (like a flash on a beat), slow smoothing for something that should drift gradually (like background color).

Try different sounds and watch the spectrum respond: a whistle produces a sharp peak at one frequency. A clap produces a broad burst across all frequencies. Speech has most energy in the 100–4000 Hz range, with formant peaks that shift between vowel sounds.

Multi-Parameter Mapping

The creative power of audio reactivity comes from mapping multiple audio features to multiple visual parameters simultaneously. Different frequency bands can drive different aspects of the visual:

open example in new window

This sketch creates a layered visualization where:

  • Bass (kick drums, low rumble) drives a pulsing center mass
  • Mid (vocals, melodic instruments) creates an orbiting ring
  • Treble (hi-hats, sibilance, brightness) scatters sparkles

Each layer responds to different sounds, so a full music track creates a rich, multi-layered animation where every element of the mix has its own visual counterpart.

Beat Detection with Thresholds

A simple form of beat detection: trigger an event when the amplitude crosses a threshold. This is crude but effective for music with clear rhythmic pulses:

let lastBeatTime = 0;
let threshold = 0.15;
let cooldown = 200;  // minimum ms between beats

function draw() {
  let level = amp.getLevel();

  if (level > threshold && millis() - lastBeatTime > cooldown) {
    // BEAT DETECTED
    onBeat();
    lastBeatTime = millis();
  }
}

function onBeat() {
  // flash, spawn particles, change color, etc.
  background(255, 77, 28);
}

The cooldown prevents multiple triggers from a single beat (since the amplitude stays above the threshold for many frames). For more sophisticated beat detection you'd look at the rate of change of the energy in specific frequency bands: a sudden spike in bass energy is more reliable than raw amplitude.
